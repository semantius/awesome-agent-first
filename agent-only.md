# Agent-only systems

Software that meets the machine-interface clauses of the [inclusion criteria](contributing.md) but fails clause 4: the people who would use it have no interface they could realistically reach for.

The test is the audience, not whether a path exists. A database reachable over SQL passes, because SQL clients are what its engineers already use. A CRM reachable only over REST or MCP does not, because the salespeople whose records these are cannot open a REST API, and telling them to have someone build a client first is the same as telling them no.

If something here is wrong about your project, open an issue or a pull request with a link to what shows otherwise and it will be corrected quickly. Software assessed and not listed for other reasons is in [considered.md](considered.md).

They are recorded here rather than in the readme because agent-first is not agent-only. The distinction is the point of the main list, and the clearest way to hold it is to name the software on the other side of it. Being here is a description, not a verdict. For some operators an agent-only system is exactly the right choice, and the entries below all say plainly what they are.

- [Crane Ledger](https://craneledger.ai) - Double-entry accounting ledger with a chart of accounts, transactions that are drafted, posted and reversed, invoices, bills, reconciliations, multi-currency and consolidated sub-organizations over REST and a streamable MCP endpoint, described by an llms.txt addressed to agents, OAuth 2.1 with RFC 9728 protected-resource metadata and the scopes `ledger:read`, `ledger:write` and `ledger:admin`, and organization-scoped API keys limited per resource to read, write or delete, with expiry and rotation. An agent bootstraps its own organization and key through `POST /accounts/master` without a person signing up. In its own words, AI tools "act as the generative UI over MCP or REST". Its human dashboard is documented for sign-in, OAuth consent, billing, API keys and support tickets, and not for reading or keeping the books. (`hosted`, `MCP`, `REST`)
- [CRMKit](https://github.com/crmkit/crmkit) - CRM driven over a plain-text HTTP API, with an MCP endpoint whose one generic tool calls that same API, admin and member roles per workspace, revocable tokens and search across every entity type. Headless by design, in its own words "no UI, no SDK", and "the agent (ChatGPT, Claude, Cursor, …) _is_ the interface". (`MIT`, `self-host`, `MCP`, `REST`)
- [headless-erp](https://github.com/Paulpandian-ai/headless-erp) - ERP exposing typed business operations over MCP and A2A, with an HTTP facade and an OpenAPI document over the same surface, every write split into a simulate step and a commit returning an Ed25519-signed receipt, scoped admin, agent and human tokens, and approvals routed to human-only tokens. In its own words "an ERP kernel with no user interface". The same author publishes a separate web console, keel-console, which has no licence file and so is not something anyone may use. (`Apache-2.0`, `self-host`, `MCP`, `REST`)
- [Nakatomi](https://github.com/mrdulasolutions/NakatomiCRM) - Headless CRM exposing every primitive as an HTTP endpoint alongside a streamable MCP endpoint, with custom fields and custom object types an agent defines, a self-describing schema manifest, an agent card and capability-scoped API keys. In its own words "No UI to click". Its only page for people is an optional, off-by-default dashboard that it describes as "a read-only view of activity, pipelines, and webhook state". (`MIT`, `self-host`, `MCP`, `REST`)
- [Rowset](https://rowset.lvtd.dev) - Dataset backend for agents over a hosted MCP server, a REST API and a Go CLI, with typed and described columns, row CRUD by index value, relationships between datasets, exports and optional hybrid vector and lexical search. Every dataset belongs to one account, and its API keys are account-wide at one of three levels: read, read and write, or admin. One of its stated design principles is "Keep humans out of row operations", and the human interface is "a small human UI for agent handoff, settings, recent datasets, exports, and preview review", with read-only public previews for sharing. The repository has no licence file, so it would also fail the quality bar. ([Source Code](https://github.com/LVTD-LLC/rowset)) (`hosted`, `self-host`, `MCP`, `REST`, `CLI`)
